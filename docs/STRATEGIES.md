# Strategy guidance and evidence

The terminal and Space use the same Rust search controller. The editor discovers a compact index of skills and requests detailed guidance only for the approach it is considering. Capability status comes from the loaded model worker, reference availability and current inspection. A skill is guidance for the next measured experiment, not a promise of improvement or permission to use an unavailable operation.

Each proposal should identify a strategy, describe its application, explain the expected measurable effect, and reflect briefly on previous measured candidates. At the first turn there are no previous candidate results. Later summaries should distinguish target gain, validation loss, preservation regressions, rejected proposals and flat results. The public summaries do not expose a provider’s private reasoning.

## Discovery before detail

The initial editing request pre-briefs essential inspection and edit tools with compact contracts, a short advisory skill index and current measurement summaries, not the full skill library, tensor manifest or complete history. The editor can request a skill, a page of eligible targets, grounded token candidates, prior measured turns or observed answers. Behavior diagnostics include repetition, output-limit endings and reference/preservation failures, without changing acceptance scores. Full non-test answers can be read in 2,048-character pages. Selected forward activation probes produce compact evidence and opaque state-bound handles rather than dumping vectors into context. The controller executes these read-only requests and supplies bounded results. It does not expose arbitrary files, shell commands or sealed test examples. Loading a skill is not applying a patch. The most recent target and token pages stay in a bounded working set across stateless provider calls; prior tool payloads are not accumulated. Skills suggest approaches, rather than whitelist strategies: a custom public hypothesis can use genuinely supported operations after inspecting its targets and token IDs. Prefer the provided measured primitives over inventing a custom gradient optimiser; no arbitrary optimiser or shell execution tool is exposed.

The editor should first identify the observed failure, choose a relevant available skill, inspect only the targets and evidence needed for that choice, and then propose one bounded experiment. A specific non-test reference error favours a contrastive reference-directed hypothesis. A token-specific error may justify an inspected output-row experiment. Prior preservation failures favour less scope, smaller strength or an available preservation-aware primitive. A previous useful direction supports measured refinement. Random forward-only search remains a fallback when no supported directed hypothesis is available. These are selection heuristics, not a fixed ranking: the editor explains its choice from current measurements.

Unavailable approaches remain distinguishable from executable alternatives. Requesting details about ROME, MEMIT or patch arithmetic must not silently relabel a simpler operation as that algorithm. The worker's current operation list remains authoritative. Every additional frontier decision uses the same spend accounting as proposal generation; local read-only results do not bypass the budget.

These are character counts, not tokenizer counts. The new discovery flow must not reproduce that manifest dump. Paths are relative to that checkout. Results describe the original experiments, not Vespasian performance. The Gemma episodes used `google/gemma-3-4b-it`, revision `093f9f388b31de276ce2de164bdc2081324b9767`, family version 0.2.2. Controls retained are relative to controls the pristine model answered correctly.

## Available strategies

- `token_row_scaling`: scale one to 32 distinct inspected token rows in one canonical embedding or output table. The factor is `1 + strength`, with nonzero absolute strength at most 0.1. This changes the selected rows rather than the whole vocabulary matrix. Negative strength does not guarantee token suppression: logits depend on signed dot products, and tied embeddings can change the hidden representation as well.
- `token_row_transfer`: pair inspected destination and source rows in the same table and make a bounded blend toward each source. The requested blend coefficient is positive and at most 0.1. The delta is also capped by that coefficient times the original destination-row norm, including stored-weight rounding. The actual blend can therefore be smaller; each row receipt reports `effective_fraction`. This is not unrestricted row copying. Source rows are read before the candidate write, so multiple pairs do not cascade within one proposal.

- `reference_alignment`: use the worker’s forward-only `activation_rank_one` candidate on reference-bearing examples. Its key-normalised MLP update contrasts the desired reference-token output embedding with the currently predicted token embedding at teacher-forced prediction positions. This is a bounded forward-only heuristic, not an optimised hidden-state target, an exact gradient or the row-level operation from the original trace. It is unavailable for prompt-only data. Corpus references describe style rather than factual answers.
- `localised_scaling`: test a modest relative change to a small number of listed tensors. Whole-MLP-tensor scaling is substantially less selective than token-row editing. It remains restricted to eligible MLP down-projection tensors; use `token_row_scaling` when a grounded row-specific experiment is justified. Do not copy benchmark factors or imply equivalence.
- `measured_refinement`: retain a useful measured direction and change one parameter at a time, or reduce scope after preservation regressions. Every new proposal starts from retained weights. The same seed reproduces a random direction, but a new activation-directed edit can depend on the changed weights.
- `bounded_exploration`: a seeded low-rank or noise fallback when no measured useful direction exists. This is an explicit search heuristic, not an IWIBench-validated technique. Flat results and stopping without improvement must remain visible.

### Additional measured primitives

- `token_row_residual` is an output-table operation for reference-bearing edits. It captures the input to an ordinary linear output head, after upstream normalisation, at teacher-forced positions predicting the reference. For selected token row `i`, it accumulates `(indicator[target = i] - p(i)) × h / ||h||²` from those measured positions, then normalises the direction per row and applies the usual actual-stored-delta bound. It samples up to `rank` edit examples, with `rank` from one to 16 and at most 64 target positions per example. Every selected ID must be currently inspected, non-special and present in both the edit reference data and the sampled positions. Missing evidence is a rejection, not an invented direction. A tied output/input table is still one physical edit with effects on both roles. Input-only or nonstandard output heads are not eligible. Small positive strengths are the starting hypothesis; no generation improvement is guaranteed by the logit residual alone.
- `activation_preserve` is a preservation-aware variant of the existing contrastive MLP operation. It samples edit and preservation examples, captures up to 64 teacher-forced prediction keys per preservation example, and uses an SVD basis to project edit keys away from the sampled preservation-key row space before forming the desired-minus-predicted output-embedding outer product. A vanished projected direction is rejected. This requires both reference-bearing edit data and preservation examples; the capability must be absent when those prerequisites are missing. It protects only a measured local linear subspace, not arbitrary capabilities or all preservation answers. Validation, preservation and health measurements still determine retention.

The runtime skill describes selectors, limits and failure cases for an advertised primitive. These operation names are not claims that a particular skill ID or operator exists on every model. The current worker capabilities, target eligibility, grounded selectors and bounded edit contract determine whether a proposal can execute. Reading a particular skill or adopting its suggested strategy is not required.

All strategies obey the worker’s tensor catalogue, operation availability, strength bounds, validation policy, preservation policy and frontier budget. They never consume sealed test examples. A strategy description cannot add a tool or authorise arbitrary code execution.

## Inspect, plan, patch and measure

Before choosing a row edit, the controller obtains current model inspection: canonical table names, aliases, input/output roles, tied-weight status, table shapes and token candidates with readable pieces and row norms. Candidate IDs come from edit, validation and preservation examples, plus explicit objective or currently observed failure text. Held-out test examples remain sealed. A word can span several subword tokens, and tokenisation can differ with whitespace or context. Model-specific IDs must never be copied from a benchmark trace or another tokenizer.

Only inspected, non-special IDs within the selected table are eligible. Interpolation requires distinct source and destination IDs. A tied input/output table is one physical tensor: the worker applies its edit once, and both roles are affected. Aliases are disclosed, not treated as independent edit targets. Full-matrix scale, noise and low-rank operations are not made available on embedding/output tables.

The editor first judges the current measured answers, inspects the model, names its hypothesis and explains the proposed operation. A proposal is a plan, not an already-applied change. The worker then applies the candidate, reports the actual changed rows and stored norms, and runs evaluation. The shared controller retains or restores the candidate using its normal validation and preservation policy. The next round reflects on that measured outcome. Target improvement alone does not establish preserved copying, source meaning or unrelated capabilities.

The row operators use the same engine in the terminal and Space. Sparse row snapshots preserve pending originals and retained changes across allocations; rollback restores the previous rows. Export and fresh-checkpoint verification remain part of the controller's final result. Independent tests are required for tied and untied models, untouched rows, invalid selectors, round-trip restoration and numerical parity. These implementation checks establish operator correctness, not improved task performance.

## Capabilities not yet transferred

Exact ROME, exact MEMIT and agent-directed patch arithmetic (combine or negate measured delta handles during search) are unavailable. Durable journal patches support exact replay through the materialize-patch utility; this is checkpoint recovery, not an arithmetic search tool. Unrestricted row copying, the benchmark's stronger replacement/scaling factors, arbitrary arithmetic tensor expressions are not exposed. Selected ordinary Linear activation probes now expose measured same-target direction handles; decoder residual hooks and cross-module transfer remain unavailable. The existing `activation_rank_one` and `activation_preserve` remain bounded MLP-specific operations; `token_row_residual` uses measured output-head inputs without requiring the separate activation-probe tool. The new row operators reproduce selected-row mechanisms within narrower bounds, not an entire benchmark editing trajectory. No improvement claim is made without a new measured experiment.

Parity means the same code, inputs, opportunities and explicit constraints. It does not promise bit-identical results across different hardware, model revisions, provider sampling or GPU execution environments. Deployment resource limits must be disclosed independently of strategy selection.

## Algorithm boundaries and primary references

**ROME.** The original method edits a factual association with a rank-one MLP write using subject-position representations and context templates. Its reference implementation optimises a latent target with Adam and backpropagation; its key computation optionally applies inverse second-moment adjustment. Vespasian's existing `activation_rank_one` omits this machinery and must not be presented as ROME. See the [ROME project](https://rome.baulab.info/), [target optimisation implementation](https://github.com/kmeng01/rome/blob/main/rome/compute_v.py) and [key computation](https://github.com/kmeng01/rome/blob/main/rome/compute_u.py).

**MEMIT.** The reference implementation optimises target representations, computes activation keys and covariance-adjusted linear solves, and distributes residual updates across selected mediating layers. A sequence of bounded rank-one proposals does not implement MEMIT. Exact MEMIT requires additional model-specific infrastructure and remains unavailable here. See the [MEMIT project](https://memit.baulab.info/), [update implementation](https://github.com/kmeng01/memit/blob/main/memit/memit_main.py) and [target optimisation](https://github.com/kmeng01/memit/blob/main/memit/compute_z.py).

**Patch arithmetic.** Published task arithmetic constructs a direction by subtracting matching pretrained weights from fine-tuned weights, then scales, adds or negates those stored differences. Repeating an operation against retained weights is not necessarily replaying a fixed delta: activation directions change with the model, relative norm limits change with the current weights, and low-precision rounding changes the stored update. Exact replay, composition or reversal therefore requires measured delta handles, compatible tensor layout/base provenance and fresh evaluation. Do not claim these capabilities from seeded proposals alone. See [Editing Models with Task Arithmetic](https://arxiv.org/abs/2212.04089v3) and its [reference implementation](https://github.com/mlfoundations/task_vectors/blob/main/src/task_vectors.py).

**Measured residual row addition.** For a linear output head, a small row addition in the direction of its measured input changes that token's logit by the dot product of the delta and that input, holding the input fixed. This local algebra is not a guarantee for regenerated sequences or tied embeddings, which can also change the input representation. Measurements must come from the actual output-head input after any final normalisation, at the position predicting the selected reference token. A failed dimension, finite-value, eligible-token or supported-head check must reject the candidate rather than substitute an unrelated activation. This is an implementation hypothesis, not a published benchmark efficacy claim.

**Preservation-aware projections.** Projecting an edit key away from a finite set of measured preservation keys can remove its linear component along those sampled directions. It does not establish preservation outside that sample, through nonlinear downstream computation or after later retained edits. A vanished projected direction is a reason to reject the candidate, not to fall back silently to the unprojected update. The normal behavioural preservation and health checks are still required.

Primary source implementations were inspected on 11 November 2026. Their reported research outcomes do not establish effectiveness on Vespasian's model families or user datasets.


## Measured direction projection

`measured_direction` is optional guidance for an evidence-led hypothesis, not a required loop-fixing recipe. The editor inspects observed failures, compares productive non-test contexts and chooses a supported ordinary Linear module, explicit row IDs, sources and token positions. The read-only tool measures an output mean or mean contrast, normalizes it and returns a state-bound direction handle plus bounded input-column summaries. Full vectors remain private engine state.

For an eligible MLP tensor, `direction_projection` applies `W' = W - strength * outer(u, mask * (u^T W))` to 1–256 selected columns. The handle must match that target and its measured state. Strength is positive up to 16, rank is 1, and the actual stored delta must fit the reviewed `max_relative_norm` limit (default 0.1), including dtype rounding. The worker rejects over-limit proposals rather than silently rescaling this formula. Accepted candidate observations become the next inspection baseline; rollback preserves prior observations and invalidates candidate evidence. Correctness, preservation and the configured health policy still govern retention.

This primitive is inspired by [weight-space programming, Experiment 8](https://rikiyat.github.io/blog/weight-space-programming/) and its [published report](https://github.com/RikiyaT/lm_understand-logs/blob/main/exp8_math/runs/p50c/work_notes/final_report.md). It is not an exact reproduction: Vespasian currently lacks decoder-residual probes and cross-module direction transfer, and its default thinking-off, greedy generation and Space quotas differ from that experiment. The original report's 32,768-token thinking-on sampling and broader norm change must not be inferred from our starter results.

The isolated published diagnostic fixtures are practice-output excerpts with source attribution, not complete traces, held-out data or optimization examples. They test that the detector flags the published repetitive excerpts without flagging the productive contrast. They do not establish causal loop repair or task improvement.
